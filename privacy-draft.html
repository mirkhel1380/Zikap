Zikap is operated by Highlink LLC.

A draft description of how the current Zikap features handle information.

Service termsPrivacy noticeCancellation & refunds

1. Who this notice concerns

This draft describes data handling in the current Zikap website, customer workspace and separate owner portal. Zikap is operated by Highlink LLC. Its public privacy contact and registered business details must be completed before this notice is adopted.

2. Information the service processes

  • Accounts: name, email address, salted password hash, hashed recovery information, session records and account timestamps. Account email ownership is not currently verified.
  • Projects: website/page addresses, package and stored price, topic, language, market, goals, status, reports, project messages, read acknowledgements, revision requests and customer-managed action plans, support request subjects/topics/statuses and their conversations, plus owner-only internal review checklists and notes.
  • Payments: Stripe checkout/payment references, amount, currency, mode, recorded payment/refund status and processing timestamps. Card details are entered on Stripe’s hosted checkout rather than in Zikap’s project forms.
  • Website checks: requested public URLs, sampled HTML observations and evidence. Account-saved checks can also include optional AI suggestions and usage reservations.
  • Request metadata: network metadata processed by the hosting service and application rate-limit counters using hashed address-derived keys. These support operation and abuse prevention.

3. Why this information is used

Information is used to manage accounts and access, review project requests, confirm agreed scope, deliver work, support project conversations, record payment events, operate website checks and apply safety and usage limits. The current service does not provide a public directory of customers or reports.

Specialist project information is visible to the authorized owner through the separate administration workspace. A private receipt can also authorize access to its corresponding project, so it must be kept secret.

4. Hosting, payments and optional providers

  • GitHub Pages serves the public website and its assets. Its infrastructure processes visitor requests under GitHub’s own terms and privacy practices.
  • Cloudflare hosts the account/API and independent owner applications and the D1 database. It processes requests and stored service records.
  • Stripe processes checkout/payment information. Its privacy practices also apply to Stripe-hosted checkout and its payment records.
  • Cloudflare Workers AI, when activated: the separate AI-consent step shares only finding IDs, fixed check codes, severity/category and human-review flags. The current prompt construction excludes raw page text, website addresses, names, account details, reports, messages and receipt keys. Suggestions and usage reservations are saved in the customer’s private review record.
  • Resend, when transactional email is activated: sending uses a recipient address, configured sender/reply address and a short notification containing an order reference, package title or payment amount. Reports, messages, names, page URLs, passwords and receipt keys are excluded from the templates. Sending is a separate configuration step.

Provider operation can involve processing outside the visitor’s country. The final notice needs the operator’s actual legal and transfer disclosures; this draft does not make a blanket data-residency or regulatory-compliance promise.

5. Cookies and browser-local tools

The customer workspace uses an essential secure session cookie with a seven-day lifetime. The owner portal uses a separate session cookie. Signing out revokes the current session; password replacement or account recovery revokes existing sessions.

Browser-local HTML checking and local CSV analysis do not send the pasted file contents through those local tools. A URL-based website check is different: the server requests the public pages. The content planner stores a plan on your device only when you choose its device-save option. Device copies and downloaded files are under your control and are not removed by signing out.

The current public site does not include Zikap advertising pixels or a Zikap marketing analytics integration. Hosting and checkout providers can process their own operational information.

6. Storage and retention

  • Private AI-review checks expire from customer access after seven days. Expired rows are purged when another account-saved check is created; this is not a promise of physical deletion at an exact minute.
  • Account sessions expire after their stated lifetime. Expired sessions and rate-limit records are cleaned through service operations.
  • Order history retains up to twenty previous saved states per order. That is a rolling recovery feature, not a complete backup.
  • Account, project, message, action-plan, payment and notification records currently have no automatic general-purpose retention period configured. A deletion request needs review, and some payment-linked records are protected from ordinary order deletion.
  • Started notification attempts can store the rendered recipient/sender payload and provider acceptance reference. Provider acceptance does not establish inbox delivery.

The owner must confirm retention periods and any necessary accounting/legal exceptions before adopting the final notice.

7. Questions and data requests

Existing customers can raise a question in their project conversation. The final notice must also provide a public privacy contact for people without a project or who cannot sign in. No unverified public email address is supplied in this draft.

Depending on the laws that apply, people may have rights relating to access, correction, deletion or other processing. The operator must confirm the applicable process, identity checks and response requirements. Zikap does not currently expose an automatic account-deletion or data-export workflow covering every record.

Account data downloads

Account & security lets a signed-in customer re-enter the current password and prepare a private JSON file. It includes the profile, currently linked project briefs and reports, project conversations, customer action plans, recorded payment summaries, unexpired saved website checks and account support requests with their conversations. Private owner work, security credentials, receipt keys, processor secrets and browser-only tool data are excluded.

The authorization lasts up to ten minutes and is tied to the same login session. Only its hash is stored. The file is assembled in the browser and remains available there until the page is cleared, reloaded or another download is prepared. Zikap does not create a stored server archive. It is a collection across successive reads, so concurrent record changes can affect the result. A download does not erase an account or change a payment. The current file limit is 50 MiB and 1,000 records; an incomplete preparation does not offer a completed file.
